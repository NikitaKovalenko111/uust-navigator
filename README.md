# UUST Navigator

Локальный навигатор по корпусам и помещениям УУНиТ.

**Коротко:** frontend на React + TypeScript, backend на Go, простая навигация между точками, сохранение предыдущих маршрутов в `localStorage`.

**Репозиторий:** этот проект содержит две директории: `client/` (фронтенд) и `server/` (бэкенд).

**Содержание README:** стек, запуск (Docker / без Docker), переменные окружения, функциональность, как добавить новые точки.

## Стек

- Frontend: React (v19), TypeScript, Vite, Redux Toolkit, Sass
- Backend: Go (modules), Fiber (HTTP), Elasticsearch client (для поиска точек)
- Storage: локальные JSON-файлы (`data.json`, `data2.json`) индексируются в Elastic
- Прочее: Axios, redux-saga, React Router

## Быстрый запуск (Docker)

Перед запуском обязательно создайте в папке /server/ папку /paths и туда поместите фото точек. Каждое фото должно называться id точки.

В корне проекта есть `docker-compose.yaml`. Запустите сервисы командой:

```bash
docker compose up --build
```

Это поднимет backend и (по конфигурации) необходимые сервисы.

- Backend API: http://localhost:3001/

Frontend требуется запустить отдельно (см. ниже)

## Запуск локально без Docker

1. Запустите backend (Go):

```bash
cd server
go build ./cmd/main.go
./main
```

Проверьте, что сервис слушает порт, указанный в `local.yaml` (обычно `3001`).

2. Запустите frontend (React):

```bash
cd client
npm install
```

Если для разработки

```bash
npm run dev
```

Если для production

```bash
npm run build
```

Фронтенд по умолчанию поднимется на `http://localhost:5173/`.

## Переменные окружения

Проект использует `local.yaml` в `server/config/` для локальной конфигурации сервера.

```yaml
env: "local" # dev, prod
http_server:
    http_address: 0.0.0.0:3001
    http_timeout: 4s
    http_idle_timeout: 60s
elastic:
    address: http://elasticsearch:9200
    username: username
    password: password
```

Файл .env

```bash
CONFIG_PATH=./config/local.yaml # Путь до конфига
```

## Функциональность

- Построение маршрута между двумя точками (форма в левом блоке)
- Автодополнение точек (поиск через `/points?query=...`)
- Просмотр пошагового маршрута и прогресс (центральный/правый блок)
- Сохранение предыдущих маршрутов в `localStorage` (ключ `uust:navigator:routes`)
- Модальное окно с историей маршрутов и восстановлением
- Новая страница `/points` — список всех точек и локальный поиск

## Как добавить новые точки в навигатор

- Откройте файл `server/data2.json` — в нём хранятся исходные точки в виде словаря `{ id: Point }`.
- Добавьте новый объект точки с уникальным `id` и полями:
    - `description` — отображаемое имя точки
    - `nums` — список кабинетов/номеров (массив строк)
    - `tags` — список ключевых слов
    - `photo` — путь к файлу изображения в папке `paths/`

Пример записи в `data2.json`:

```json
"point-123": {
  "description": "Новый кабинет 123",
  "nums": ["123"],
  "tags": ["лаб", "физика"],
  "photo": "point-123.png"
}
```

Дальше либо вручную пропишите в data.json все пути от этой точки до всех остальных (и также от других точек до нее, что долго), либо в отдельном json файле пропишите граф всех точек и прогоните через графовый алгоритм - получите data.json (главное, чтобы поля были теми же).

Перезапустите сервер и все новые точки автоматически проиндексируются в elastic

## Роуты API (основные)

- `GET /points?query=...` — поиск по точкам (Elastic)
- `GET /points/all` — получение всех точек (список из `data2.json`)
- `GET /points/:id` — получение данных точки и фото (Base64)
- `GET /path/navigate?start=ID&end=ID` — построить маршрут
